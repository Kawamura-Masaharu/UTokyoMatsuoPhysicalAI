# 1～3 分のデモ動画

目的は、**曖昧な指示・未登録地点では移動を始めず、明確な訪問順を実行できること**を一続きの動画で示すことだ。課題の 10/8 版に基づき、動画は 1～3 分以内に収める。2 倍速を使う場合は動画内または概要欄に明記する。

## 録画前の準備

- [環境手順](ENVIRONMENT.md) に従い、Gazebo / Nav2 / AMCL が動いている状態にする。
- API キーの入力、ROS の設定、リポジトリールートへの移動は録画前に済ませる。
- 画面左に実行用 Terminator、右に Gazebo を配置する。RViz は必要に応じて切り替えて、自己位置や経路を示す。
- ロボットは A (受付) 付近から開始する。最終確認の A → B → A の実行後なら、その停止位置を利用できる。
- 氏名・所属・メールアドレス・API キーが映る画面を含めない。

LLM に座標・現在位置・画像を渡しているような説明はしない。Gemini は地点名から ID の訪問順を生成し、センサーによる自己位置推定と移動制御は AMCL / Nav2 が担当する。

## 構成例 (約 2 分～2 分 30 秒)

| 時間の目安 | 操作・画面 | 伝えること |
|---|---|---|
| 0～15 秒 | 地図と A=受付、B=倉庫を示す | 自然言語 → Gemini の訪問順 → 検証 → Nav2 の移動 |
| 15～35 秒 | 下記の操作 1 | 戻り先が曖昧なら確認質問を返し、動かない |
| 35～55 秒 | 下記の操作 2 | 未登録地点を含む指示は、既知地点への部分実行もしない |
| 55～120 秒 | 下記の操作 3 | `["A", "B", "A"]` と全区間の `SUCCEEDED`、Gazebo の移動 |
| 120～135 秒 | 結果とログの一部 | 入力・計画・区間結果を記録し、実行を確認できる |

実際の API 応答やシミュレーション速度で時間は変わる。記録済みの A → B → A の 2 回は、API と準備・終了処理を含めて約 54 秒だったが、撮影時の時間は一度通して確認する。

## 操作 1: 戻り先が曖昧な指示

**以下の 3 操作はすべて通常実行で、`--plan-only` を付けない。** コマンドはリポジトリールートで実行する。

```bash
/usr/bin/python3 -u nav_gemini.py --poses-dir ./poses --log-file ./logs/gemini_nav.jsonl \
  '倉庫に行って戻って'
```

`status: clarify`、`route: []` と戻り先を尋ねるメッセージを見せる。Gazebo のロボットが動かず、移動前にプログラムが終了することを確認する。

字幕例: **「戻り先を推測せず、確認質問を返す」**

## 操作 2: 未登録地点を含む指示

```bash
/usr/bin/python3 -u nav_gemini.py --poses-dir ./poses --log-file ./logs/gemini_nav.jsonl \
  '受付、検査室、倉庫の順に回って'
```

検査室が未登録として `clarify` / `[]` になることを見せる。受付への先行移動も行わない点が、この例の見どころになる。

字幕例: **「行き先が確定するまで、一部の地点も実行しない」**

## 操作 3: 受付 → 倉庫 → 受付

```bash
/usr/bin/python3 -u nav_gemini.py --poses-dir ./poses --log-file ./logs/gemini_nav.jsonl \
  '受付、倉庫、受付の順に回って'
```

`status: ready`、`route: ["A", "B", "A"]` を表示し、その後の移動を見せる。

**開始時に A 付近にいるため、最初の A はほぼその場で到着判定される。** 続いて B へ移動し、A へ戻るところを撮影する。最後に 3 区間の `SUCCEEDED` と実行完了を見せる。

字幕例: **「明確な訪問順を実行し、区間ごとの成功を確認する」**

確認後の入力は、以前の会話に対する短い返答ではなく、コマンドごとに独立した指示全文だ。対話履歴を保持した自動的な再計画として説明しない。

## 画面で示す結果

必要なら最後に今回のログを表示する。

```bash
tail -n 12 ./logs/gemini_nav.jsonl
```

文字が読める大きさにし、入力、計画、各区間の結果が分かる部分を見せる。Gazebo での動作とログによる到着判定を対応させる。保存座標と完全に同じ位置へ停止する精度や、任意の指示の成功率は主張しない。

待ち時間を編集で短縮する場合も、指示・計画・実行結果の対応が分かる構成を保つ。走行を 2 倍速にした部分には「2 倍速」と明示する。
